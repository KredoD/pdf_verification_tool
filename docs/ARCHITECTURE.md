# Архитектура сервиса

Сервис предназначен для первичной проверки пакета документов ВНИИИМТ. Пользователь загружает эталонный документ и проверяемые документы. Система извлекает реквизиты, сверяет их и формирует отчет.

## Поток обработки

1. `app/main.py` — веб-интерфейс и API.
2. `app/extractors.py` — чтение файлов PDF/DOCX/XLSX/TXT, OCR для сканов и картинок, извлечение сущностей.
3. `app/artifact_rules.py` — проверка обязательных артефактов по сценариям УПП/OEM/РФ-производитель.
4. `app/verification.py` — сверка реквизитов с эталоном.
5. `app/report_builder.py` — HTML/DOCX/JSON отчет.
6. `scripts/run_local_check.py` — запуск без браузера.
7. `tests/test_smoke.py` — минимальный тест работоспособности.

## Почему правила вынесены отдельно

Бизнес-правила могут меняться чаще, чем парсеры и интерфейс. Поэтому сценарии проверки лежат в `app/artifact_rules.py`. Технический директор может менять обязательные артефакты без переписывания OCR, веб-интерфейса и генерации отчетов.

## Ограничения MVP

- OCR зависит от качества скана и наличия Tesseract.
- Извлечение адресов сделано эвристически и требует расширения на реальных пакетах.
- Для промышленной эксплуатации нужна очередь задач: Celery/RQ/Background worker.
- Для больших архивов нужен прогресс-бар, кеш OCR и ограничение размера файлов.
