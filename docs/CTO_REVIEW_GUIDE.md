# Инструкция для технического директора: как проверять проект

## 1. Что смотреть в первую очередь

1. `app/artifact_rules.py` — бизнес-логика обязательных артефактов.
2. `app/extractors.py` — извлечение ИНН, ОГРН, телефонов, email, организаций, классов риска, НКМИ, лицензий и адресов.
3. `app/verification.py` — сверка с эталоном и формирование статусов.
4. `app/report_builder.py` — доказательная часть отчета: откуда взято значение.
5. `tests/test_smoke.py` — минимальная проверка, что конвейер не сломан.

## 2. Как запустить

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
pytest -q
uvicorn app.main:app --reload
```

Открыть в браузере: `http://127.0.0.1:8000`.

## 3. Как профессионально принимать такую работу

Обычно код передают не одним Word-файлом, а как репозиторий или ZIP с такой структурой:

- исходный код;
- README с запуском;
- архитектура;
- описание бизнес-правил;
- requirements / lock-файл зависимостей;
- тесты;
- sample data;
- пример отчетов;
- changelog;
- known limitations;
- список вопросов к заказчику.

Word-документ с кодом может быть приложением для нетехнических согласований, но основная проверка должна идти по репозиторию/ZIP.

## 4. Что еще нужно для production

- Авторизация пользователей.
- Удаление документов после обработки.
- Логи и аудит действий.
- Очередь задач для тяжелого OCR.
- Хранилище результатов с ограниченным сроком жизни.
- Тестовый набор реальных пакетов: УПП, OEM, РФ-производитель, общий пакет.
